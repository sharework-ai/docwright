# 设计：生成参数机制——硬上限与用户意图注入（dynamic parameters）

Status: IMPLEMENTED (2026-10-11)。
Date: 2026-10-11
关联: docs/designs/docwright-mvp.md 第 3.1/3.7 节、docs/designs/convergence-detection.md（maxRounds 与终止语义的接口）、TODOS.md D3-params

## 问题

两个需求，一条通道：

1. **重试轮数的硬护栏**：无论怎么重试都不超过一个总上限（成本护栏）；同时允许 pack 按领域给默认值（预算报告就是比 Plan 需要更多轮）、用户在对话中临时调整（"这次多试几轮"）。
2. **pack 的可调参数**：pack 需要向用户暴露旋钮（如 `cfpUpper`、`tone`）。用户意图出现在对话里，需要**确定性地**到达生成与校验两侧，并被回执记录。

> 本设计经三轮推敲定案（每轮自省 → 会话级联 → 最小桥），推演记录见文末附录，正文只写终案。

## 设计（终案）

核心洞察：**按参数给谁消费切一刀**。生成侧参数零机制（prompt 承载默认，LLM 读对话即用）；校验侧参数走最小桥——工具调用参数。原则：**LLM 是意图的识别者，不能是校验值的携带者**。

### 1. 轮数硬上限（三层默认 + 一个绝对钳制）

```
生效轮数 = clamp( maxRounds 参数 ?? pack 声明 ?? Config 全局默认 , ceiling )
```

- `doc_generate` 增加可选参数 `maxRounds: int`——用户"这次多试几轮"由模型转述至此（用户意图经工具调用进 session log，符合 model-visible ⟺ logged）。
- pack manifest 可选 `maxRounds` 字段（领域调优，如预算报告 8 轮）。
- Config `maxIterations`（现有，默认 5）仍为全局默认；新增 Config `maxRoundsCeiling` 为**绝对上限**（宿主运维持有），**任何层穿透即 clamp**——没有它，"可覆盖的上限"只是多个默认值，不是硬上限。

### 2. pack 参数（声明即白名单）

manifest 增 `params` 声明：

```json
"params": {
  "cfpUpper": { "type": "number", "default": 50, "min": 20, "max": 100, "description": "CFP 建议区间上限" },
  "tone":     { "type": "string", "enum": ["formal", "plain"], "default": "formal" }
}
```

- **声明即可调，未声明即不可调**——pack 没暴露的旋钮谁都不能拧（含模型）。
- 加载期校验参数 schema 本身合法（misconfiguration fails loud）；`doc_generate` 调用期校验传入值：未知参数、越界/出枚举 → 报错并列出可用参数（错误内容契约）。
- **clamp 来源按声明者走**：pack 参数用声明里的 min/max/enum（作者钳制），`maxRounds` 用 ceiling（运维钳制）——每个值都被它的声明者钳住。
- 注入：`{{params}}` 槽位把生效值（含默认）渲染进生成 prompt，模型看得见有哪些旋钮、当前是什么值；规则可引用参数名替代字面量（如 maxLength 规则引用 `cfpUpper`）。
- **闸门边界**：params 只能调 pack 声明的数值/枚举旋钮，不能增删规则、不能改 schema、不能降严重度——校验的**结构**始终是 pack 作者与运维的领地。

### 3. 回执与复验（as-run 快照）

- 回执记录每次生成的 as-run `params`、生效 `maxRounds` 及其来源层（arg / pack / config）——每份文档都能回答"当时为什么跑了几轮、按什么标准校验"。
- `doc_validate` 复验**默认用回执记录的参数**（复验历史文档按当时的标准）；显式传参可测试其他取值。参数漂移与 packVersionStale 一样显式可见，不静默改写复验结果。
- 回执 formatVersion 维持 1（全部为附加可选字段）。

## 明确不做的（及接受的代价）

- 不做 doc_configure 工具、会话参数存储、跨会话用户偏好层、多层级联优先级。
- **诚实代价**：意图捕获从"工具强制"降为"模型自觉"——用户说了 `cfpUpper=45` 而模型漏传参数，就按默认跑，没有机制兜底拦截。缓解是两件便宜的事：`{{params}}` 把旋钮与当前值渲染进 prompt（模型看得见）、回执记录生效值（事后可对账）。接受"LLM 驱动"应有的方差。

## 验收标准（草案）

1. `params` 含未知参数名或越界值 → 调用期报错，错误列出可用参数与约束。
2. 未声明 `params` 的 pack 收到 params → 调用期报错。
3. `maxRounds` 超 ceiling → clamp；不传时按 pack 声明 → 全局默认回退链取值。
4. 规则引用参数：as-run 值参与校验；换值生成同一素材得到不同校验结果（证明参数真的到达了 checker）。
5. 回执含 as-run params 与生效轮数来源；`doc_validate` 用回执参数复验，结果与生成时一致；显式传参可覆盖。
6. `{{params}}` 渲染进 prompt（默认值 + 覆盖值），prompt 快照测试锁定。

## 附录 A：推演记录（已定案，不再重开）

> 本附录回答"为什么终案长这样"。以下两案已否决——重新提议前先读否决原则；凡触及原则的变体（换壳自省、隐性会话改参、模型自评质量分）一律视为已答。

### 已否决（第一轮）：每轮生成前自省动态参数

模型每次生成前按 meta-schema"自言自语"产出本轮动态参数（roundPlan）。

- 否决原则：**运行期不得由模型变更任何影响校验或终止的参数**——模型可借参数给自己加预算、放松终止阈值，闭环护栏被它自己养出来的机制绕开。
- 附加否决理由：独立自省调用让每轮成本翻倍；运行期参数漂移使回执不可精确重放。

### 已否决（第二轮）：会话开始参数确认 + 多层级联

对话开始时插件先做参数确认（doc_configure 工具 + 会话级覆盖存储），运行时参数按"内置默认 < pack 声明 < 用户设置 < 会话临时"级联，ceiling 在最外层。

- 否决原则：**机制不得重复 LLM 已在完成的识别工作**——用户意图最终仍由 LLM 识别，级联管道（configure 工具、会话存储、四层优先级）是为同一件事再修一套系统；插件亦无"会话开始"钩子，确认仪式只能靠 prompt 约定。
- 附加否决理由：全参数级联（含按 pack 键的用户设置层、会话改参的 as-run 语义）整体过度设计，收益配不上复杂度。

### 终案推导

关键洞察是**参数给谁消费**决定它需要什么机制：生成侧参数 LLM 直读即可（LLM 就是正确实现）；校验侧参数的值必须确定性到达 checker 与回执——"LLM 可以识别意图，但不能携带值"。桥 = 工具调用参数（`params` / `maxRounds`），级联塌缩为"pack 声明默认 < 模型转述的用户意图"+ ceiling。

## 附录 B：决策记录

- 2026-10-11 三轮推敲定案（自省 → 会话级联 → 最小桥），否决原则见附录 A。
- 用户关键判断一：参数识别最终必由 LLM 完成，机制不应重复它——据此砍掉会话级联。
- 用户关键判断二（终案保留的边界）：LLM 可以识别意图，但校验侧的值必须经类型化工具参数进入确定性代码与回执。
- 实现期定案（原开放问题 1-4）：参数声明用 loader 内独立全量校验（assertParamSpec，不复用规则校验）；规则引用语法取 `{"param": "name"}`（结构化、可快照）；命名取 `maxRounds`（manifest/pack 级），`config.maxIterations` 保留为全局默认；轮数耗尽 reason 仍为 `max-iterations`（与 convergence reason 枚举同集）。
